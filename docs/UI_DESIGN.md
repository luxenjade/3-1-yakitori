# 🎨 UI/UX 設計仕様書 (`UI_DESIGN.md`)

文化祭の現場（騒音・混雑・焦り・端末の多様性）において、**「説明書なしで直感的に操作でき、押し間違いや認識相違を物理的に防ぐ」** ためのデザインシステムおよび画面仕様です。

---

## 🎨 デザインシステム・共通ガイドライン

### 1. カラーパレット (Tailwind CSS)

意味とアクションに直結した配色を行い、視覚的な誤操作を防ぎます。

- **メインブランド (プライマリ):** 黒系の落ち着いた色
- **ステータス・決済種別:**
- **現金 (Cash):** `emerald-600` (`#059669`) / お札・安全のイメージ
- **交通系IC:** `sky-500` (`#0EA5E9`) / 電子マネーのイメージ
- **調理待ち (Pending):** `slate-500` (`#64748B`)
- **調理中 (Cooking):** `amber-500` (`#F59E0B`)
- **提供可・完成 (Ready):** `emerald-500` (`#10B981`) / デカデカと点滅通知
- **遅延警告 (Warning):** `rose-600` (`#E11D48`) / 3分以上経過した注文
- **完売 (Sold Out):** `zinc-400` (`#A1A1AA`) / グレーアウト＆タップ不可

### 2. タッチターゲットとインターフェース原則

- **最小タップ領域:** ボタンおよび操作エレメントは、最低でも `h-12 (48px)` 以上、主要アクションボタンは `h-16 (64px)` 以上を確保（指の太い人や焦った時の押し誤りを防止）。
- **フィードバックの視覚化:** ボタンタップ時は必ず `active:scale-95` のアニメーションを付与し、押した感覚を明確化。
- **フォントサイズ:** 重要情報（注文番号・金額・数量）は `text-2xl` 〜 `text-5xl` の超大型フォントを使用。

## 📱 各画面 (UI) 構成仕様

### 1. モバイルオーダー画面 (`/`)

- **ターゲット:** 一般客（スマホ / モバイル表示最適化）
- **主なコンポーネント:**
- **ヘッダー:** リアルタイム待ち人数・目安時間の表示。
- **商品カードリスト:**
- 商品画像、名称、価格、現在のステータスバッジ（`在庫あり` / `残りわずか` / `完売`）。
- 在庫 `0` の場合、カード全体をグレーアウトし `disabled` 化。

- **下部固定カートバー:** 選択中の点数と合計金額を表示し、「仮注文を確認する」ボタン（`w-full h-14`）。
- **仮注文完了モーダル / 画面:**
- 大型の **仮注文QRコード** (`qrcode.react` 描画)。
- 万が一のスキャン失敗用 **6桁英数字コード (`text-3xl font-black`)**。
- 「レジで決済するまで商品は確保されません」の注意書きテキスト。

- **呼出・待機ステータス画面 (決済完了後):**
- **偽造防止グラデーション:** 背景でゆっくり動き続けるカラーアニメーション（スクショ対策）。
- 自分の引き換え番号 (`text-6xl`) と、現在の呼出番号 (`text-3xl`)。

---

### 2. 会計レジ (POS) 画面 (`/pos`)

- **ターゲット:** 会計スタッフ（スマホ・タブレット縦持ち / 高速操作優先）
- **主なコンポーネント:**
- **スキャナー領域 (上部 / モード切替):**
- WebカメラによるQRスキャンビューア（`html5-qrcode`）。
- カメラ不動時の「6桁コードテンキー手入力」切り替えタブ。

- **注文内容確認エリア (中央):**
- スキャンした仮注文の明細（商品名、数量、小計、合計金額）。
- スマホ非対応のお客さん用に、手動で数量変更 (`＋` `ー` ボタン: `h-12 w-12`) ができるUI。

- **決済実行領域 (下部固定):**
- **「現金でお会計 (`bg-emerald-600`)」** と **「交通系IC (`bg-sky-500`)」** の超大型2分割ボタン。

- **全画面決済完了トースト:**
- 決済確定時、画面全体が1秒間「緑色＋巨大チェックマーク」で発光し、成功を確信させてから次のスキャンへ即時復帰。

---

### 3. キッチンディスプレイ画面 (`/kitchen`)

- **ターゲット:** 厨房スタッフ（iPad・タブレット横持ち / 据え置き）
- **主なコンポーネント:**
- **サマリーヘッダー (最上部):**
- 全体の作成待機数カウント（例: 「🪵 焼きそば: 合計 12個」「🍹 ジュース: 合計 5個」）。

- **注文カードグリッド (メインエリア):**
- 古い注文順（昇降順）にグリッド配置。
- 各カードに「引き換え番号 (`#105`)」「経過時間 (`3分経過`)」「商品明細リスト」。
- **経時警告:** 3分以上放置されているカードは背景が `bg-rose-50 border-rose-500` に変化しパルス点滅。

- **ステータス変更アクション:**
- カードタップ/スワイプで `調理中` ➔ `提供可` へ遷移。
- 誤操作防止のため、「完了（手渡し）」は **1秒間の長押し (Long Press)** または **右スワイプ** で実行。

- **緊急救済ヘッダー:**
- 「履歴・復元」ボタン。過去に誤って完了にした注文を1タップで厨房画面に戻す機能。

---

### 4. サイネージ画面 (`/signage`)

- **ターゲット:** 待合モニター・一般客（大型ディスプレイ / 遠目からの視認性重視）
- **主なコンポーネント:**
- **呼出中番号エリア (左側 / メイン):**
- 「お呼び出し中の番号」を巨大カード表示 (`text-7xl font-black text-emerald-500 animate-bounce`)。

- **準備中番号エリア (右側上部):**
- 「ただいま調理中」の番号リスト (`text-3xl text-slate-400`)。

- **リアルタイム完売情報・売上メーター (右側下部):**
- 完売商品のリアルタイム掲示板。
- クラスの売上目標達成度プログレスバー（お祭り感を演出）。

## 🛠️ エラーハンドリング・UX保護機能

1. **画面スリープ防止 (Wake Lock API):**

- お客さんの「仮注文QR表示画面」「呼出画面」および「キッチンディスプレイ」では、ブラウザの Wake Lock API を起動し、画面の自動消灯・ロックを物理的に防止。

2. **誤離脱・誤リロード防止:**

- スタッフ用画面 (`/pos`, `/kitchen`) では `beforeunload` イベントをハンドリングし、スワイプ等による予期せぬページ離脱・再読み込みをガード。

3. **オフライン・ネットワーク低速時のフォールバック:**

- ネットワーク切断時は画面上部に `bg-amber-500` の「オフライン・自動再接続中」メッセージバーを常時固定表示。
